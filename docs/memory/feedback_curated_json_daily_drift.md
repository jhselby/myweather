The 18 files under `weather_collector/data/*_curated.json` (lc_correction_table, wg_l3_skip_table_curated, dp_residual_persistence_curated, c1_confidence_curated, etc.) are **production config** the deployed collector reads via `Path(__file__).resolve().parent.parent / "data" / ...`. They only take effect after `make deploy-collector` packages them into the Cloud Function.

**They also get regenerated by every daily digest run** on Joe's Mac — `generated_at` timestamp shifts, values drift a few percent as windows roll. So `git status` will typically show 15-20 of them modified even when Joe hasn't done any ship work.

**How to apply:**
- If this session did NOT include a ship that intentionally changes one of these tables' SHIP-set, **do not stage them into a commit**. They'll bundle naturally with the next intentional ship (e.g., a live-layer flip, a Stage-3 wire, a SKIP-table extension).
- If this session IS the ship that changes a table (e.g., "wire the 2 held wg L3 cells" on 08-04), stage only the JSON(s) that ship touches, not the whole daily-drift batch.
- Never bulk-stage `weather_collector/data/*.json` — it will pull in unrelated daily drift that should stay uncommitted until its own ship.
- `.cache_l5_gate_history.json` and `.cache_lc_gate_history.json` are **local-only** Fitter caches (deployed collector reads gate state from GCS, not these) — gitignored since 2026-07-29.
- Codified 2026-07-29 during v0.6.388b sweep — Joe asked "what are those JSONs, do we need them?"
